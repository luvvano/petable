# petable

Редактор графа работ (Jobs To Be Done) для macOS. Уровни — горизонтальные полосы, работы раскладываются слева направо автоматически; связи — внутри уровня (следующая работа) и на уровень ниже (декомпозиция). Документы — файлы `.petable` (JSON-конверт `{version, stages}`).

## Проекты

Проект = документ `.petable`; внутри проекта — несколько именованных графов работ (сайдбар: выбрать, «+ Новый граф», контекстное меню — переименовать/удалить). Хаб проектов (меню File → «Проекты…», ⇧⌘O) показывает проекты из `~/Documents/Petable`: создать, переименовать, открыть двойным кликом. Файлы, открытые из других мест, работают как обычные документы.

Формат: v10 — у стадии появился родитель (группы графов). Старые файлы (v1 — дерево, v2 — одна безымянная стадия, v3 — именованные стадии, дальше — core-уровень, области, свёрнутые цепочки) читаются и мигрируют при сохранении.

## Группы графов

Графы проекта — дерево, а не плоский список: связанные графы (сегменты одного продукта, версии гипотезы, декомпозиция большой работы в отдельный граф) собираются в группу под общим родителем.

- **Правый клик по графу → «Создать новый внутри»** — новый граф появляется под этим, с отступом.
- **Перетаскивание графа на граф** — перенос в его группу; то же в контекстном меню, пункт «Переместить» (в том числе «На верхний уровень»).
- Треугольник слева от имени сворачивает и разворачивает группу.
- Родителем работает любой граф — отдельной сущности «папка» нет: граф остаётся самостоятельным (свои уровни, undo, экспорт), группировка живёт только в списке стадий.
- Удаление графа уносит всю его группу (⌘Z возвращает целиком). Последний граф проекта удалить нельзя.
- Циклы невозможны: в себя и в собственного потомка граф не вкладывается; битые ссылки на родителя при чтении файла уезжают на верхний уровень — граф не может пропасть из сайдбара.

## Требования

- macOS 14.0+
- Xcode 16+ (Swift 6.1)
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) — только если меняете `project.yml`

## Установка с нуля

```bash
# 1. Клонировать
git clone <repo-url> petable
cd petable

# 2. (опционально) перегенерировать проект — нужно только после правок project.yml
brew install xcodegen
xcodegen generate

# 3. Открыть и запустить
open petable.xcodeproj   # схема petable, ⌘R
```

Или одной командой из терминала — Release-сборка, установка в `/Applications`, запуск:

```bash
make install
```

Другие цели: `make run` (сборка и запуск без установки), `make build`, `make test`, `make clean`.

## Тесты

```bash
# Юнит-тесты ядра (GraphCore: движок, раскладка, конверт, undo)
swift test

# UI-тесты (перехватывают фокус и клавиатуру — не запускать, пока работаете за машиной)
xcodebuild test -project petable.xcodeproj -scheme petable
```

## Структура

```
App/Sources/        — macOS-приложение (SwiftUI): оболочка с сайдбаром, канвас, документ
Sources/GraphCore/  — ядро (SPM-пакет): модель WorkGraph, интенты, раскладка, конверт файла
Tests/              — тесты GraphCore (swift-testing)
project.yml         — описание Xcode-проекта для XcodeGen
```

## Горячие клавиши канваса

| Клавиша | Действие |
|---|---|
| Tab | Связанная работа на уровень ниже |
| ⌘Return | Связанная работа справа (тот же уровень) |
| Return | Редактировать выделенную работу |
| ⌘← / ⌘→ | Сдвинуть работу внутри её области уровня |
| ⌥← / ⌥→ | Свернуть / развернуть цепочку работ уровня |
| ← → ↑ ↓ | Навигация по работам |
| Delete | Удалить работу (⌘Z возвращает) |
| Esc | Снять выделение / отменить редактор |
| ⌘K | Палитра механик ценности |
| ⌘+ / ⌘− / ⌘0 | Zoom крупнее / мельче / реальный размер |
| ⇧⌘0 | Вписать граф в окно |
| ⌘-скролл / пинч | Zoom вокруг курсора |
| Двухпальцевый скролл | Панорамирование |
| Драг по пустому месту | Панорамирование мышью |
| Двойной клик по пустому месту | Новая работа там, куда кликнули (внутри рамки области — в этой области) |
| Драг работы мышью | Перенос: другой уровень, другая область, другое место в полосе |

Все действия продублированы в меню «Граф» и «Вид»; в правом нижнем углу канваса — панель масштаба и переключатель подсказок клавиш. Текст работы вводится грамматикой `роль: хочу …` — префикс до первого двоеточия становится ролью.

## Полоса Core Jobs

Кóровые работы — опора графа, поэтому их стиль **не зависит от номера полосы**: кружок всегда размера второго уровня шкалы, цвет — тёмно-синий, полоса и её имя — в том же тоне. Вставили уровень сверху, перенесли отметку Core Jobs, поменяли порядок полос — картинка кóровых работ не меняется, меняются только соседи. Остальные уровни живут по шкале «выше полоса — крупнее кружок».

## Области уровня

На полосе уровня **Core Jobs** можно завести **область** — отдельную рамку с собственным именем (по умолчанию «SMALL JOBS»). Смысл по AJTBD: работы **того же уровня**, которые продукт не выполняет, — малые работы рядом с кóровыми. Уровень остаётся один (тот же ряд, тот же размер узлов), меняется покрытие продуктом: рамка и контуры узлов внутри неё пунктирные.

Области бывают **только у core-уровня**: на остальных уровнях продукт и так не выполняет работы целиком — рамка ничего не различала бы. На других полосах кнопки «+ область» нет; при переносе отметки Core Jobs на другой уровень области прежнего снимаются (работы остаются на своих местах).

- Кнопка «+ область» на полосе Core Jobs (появляется рядом с курсором) — создаёт область сразу с работой в редакторе. Новая область встаёт **справа от всего содержимого полосы**, не внутри существующей: между рамками всегда зазор `zoneGap`.
- «+ работа» у правой кромки рамки — работа в эту область.
- Двойной клик по пустому месту **внутри рамки** — работа в этой области, на позиции под курсором.
- Двойной клик по имени области — переименовать; правый клик — переименовать или убрать (работы остаются на уровне).
- Перетаскивание работы в рамку/из рамки или контекстное меню работы — перенос между областями.
- ИИ-агент размечает области сам: узел с `"zone": "SMALL JOBS"` на уровне кóровых работ; `zone` на других уровнях игнорируется.

## Механики создания ценности

**⌘K** над канвасом открывает палитру: все 25 механик канона AJTBD (текст — копия
`value-creation-mechanics.md`, обновляется заменой файла в `Sources/GraphCore/Resources/`,
рассинхрон ловит тест на резолв слагов). Закрытие — **Esc**, **клик мимо палитры**
или **✕** в правом верхнем углу.

Два способа применить механику:

- **Клик по строке — взвести.** Палитра закрывается, курсор становится прицелом,
  сверху чип-подсказка («„Убить работу“ — кликните по работе · Esc — отмена»).
  Наведение на работу показывает живой призрак результата, клик — применяет.
  Механики связи целятся в линию между работами. Esc или клик по пустому месту — отбой.
- **Enter — применить к выделенному.** Клавиатурный путь: выделил работу до ⌘K,
  ↑/↓ по списку с живым призраком, Enter применяет, ⌥Enter — форк в граф-потомок.

Мёртвых плиток нет — каждая механика в одном из трёх классов:

- **Меняет граф** (7): выбор в списке рисует **живой призрак** — граф после механики
  прямо на канвасе (убитые работы гаснут и перечёркнуты, новые связи пунктиром), сверху
  строка дельты («−1 работа · −1 связь»). **Enter** применяет (⌘Z откатывает одним
  шагом), **⌥Enter** создаёт граф-потомок с применённой механикой — у него в сайдбаре
  бейдж-палочка с происхождением, переименование связь не рвёт. «Убить работу» **не
  удаляет узел**: работа остаётся на графе перечёркнутой крестиком (подпись зачёркнута,
  рёбра гаснут), живые соседи сшиваются в обход — видно, что именно убила гипотеза.
  «Вернуть работу (снять крестик)» — в контекстном меню убитой работы.
- **Меняет карточку работы** (4): работают по полям карточки (`критерии успеха`,
  `эмоции`). «Убрать негативные эмоции» применяется сразу, критериальные открывают
  редактор карточки.
- **Заметка на графе** (14): у механики нет формы над графом — она вешается стикером
  на выделенную работу.

**Каждое применение оставляет запись** — стикер-комментарий на якоре (оранжевый
бейдж на работе; у каждой механики своё изображение — SF Symbol из словаря, та же
картинка в строке палитры и в треде): применение механики — событие документа, его
след не исчезает после следующего действия. Трансформация и запись — одна
undo-группа, ⌘Z откатывает применение целиком.

**Комментарии.** Клик по бейджу на работе открывает окно комментариев узла.
Кнопка-конвертик в правом верхнем углу канваса открывает **сайдбар комментариев**
(как в Confluence): все записи механик графа с тредами обсуждения («Ответить…»),
клик по комментарию выделяет и центрирует его якорь на канвасе. Комментарий
снимается корзинкой в треде, из контекстного меню работы или ⌘Z.

Серых плиток в палитре нет: все механики одного активного цвета вне зависимости от
выделения. Нижняя панель палитры показывает **русское описание** механики и **превью
на каноническом примере графа** (что она делает — до выделения на канвасе). Enter на
механике, неприменимой к текущему выделению, взводит её — цель выбирается кликом.
Применимость — проверка типов, не совет: приложение никогда не говорит, какую
механику выбрать. Формат файла: v12 (записи механик с тредами комментариев).

## Свёрнутые цепочки

**Цепочка** — работы одного уровня, связанные слева направо (`⌘Return` строит именно её). Длинная цепочка съедает всю ширину полосы, а разбирать обычно нужно одну её часть — поэтому цепочку можно **свернуть**: работы справа уходят с канваса под счётчик у головы, полоса собирается обратно, соседние работы уровня встают рядом.

- **⌥←** — свернуть цепочку выделенной работы, **⌥→** — развернуть; то же в контекстном меню работы и в меню «Граф».
- Кнопка **‹‹** над плюсом справа (появляется под курсором) — свернуть; **счётчик скрытых работ** справа от головы виден всегда — клик по нему разворачивает.
- Вместе с работой уходит её **декомпозиция** — на всю глубину. Работа уровнем ниже, у которой остался ещё один видимый источник, остаётся на месте: пропадает только линия к скрытой.
- Цепочка обрывается на границе уровня и на границе области: связь вниз (декомпозиция) и связь в соседнюю область продолжением цепочки не считаются.
- Голова цепочки видна всегда. `⌘Return` на свёрнутой работе сначала разворачивает её — новая работа не появляется в невидимом месте.
- Сворачивание — часть документа (файл, ⌘Z, PNG-экспорт): граф открывается в том же виде, в каком его закрыли, а на картинке у головы стоит тот же счётчик.
