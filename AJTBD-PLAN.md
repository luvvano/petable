Дата: 2026-07-23. Основа: канон Next Move Theory (`~/.claude-personal/Next-Move-Theory-Canon`), nmt-скиллы и текущий код приложения.

## 1. Что уже есть

| Область | Реализация |
|---|---|
| Граф работ | `WorkGraph` (Sources/GraphCore/WorkGraph.swift): уровни-полосы, узлы `role: verb`, рёбра «декомпозиция вниз / последовательность в уровне», чистый `GraphEngine` + undo |
| Интервью | `Research.swift`: два AJTBD-шаблона (разовая/регулярная работа), 8 элементов как текстовые вопросы, плейсхолдеры `{решение}` и др. |
| Агент | `AgentService.swift`: NMT-промпт (8 элементов, уровни Big/Core/Small/Micro, проблема = следствие), возвращает интервью + граф |
| Персистентность | JSON-envelope v5, миграции v1→v5, экспорт/импорт JSON/Markdown/PDF |

## 2. Чего нет (gap против канона)

1. **Карточка работы** — узел графа хранит только `verb` + `role`. Нет 8 элементов, критериев успеха, веса (частота/бюджет/важность 1–10), типа работы (Regular/Orientation/Tax/Fake/Emotional/Viral).
2. **Семантика уровней** — уровни это индексы массива, а не типы Big/Core/Small/Micro относительно продукта. Частично закрыто (envelope v7): у уровня флаг `isCore` — core-уровень (работы, которые продукт выполняет целиком) есть в каждом графе, ровно один, защищён от удаления; интент `setCoreLevel`, `coreLevel` в payload агента. Envelope v8: **области уровня** (`LevelZone` + `zoneID` у работы) — отдельная рамка на той же полосе для работ, которые продукт не выполняет: малые работы живут рядом с кóровыми на одном уровне, а не «этажом ниже». Остальные типы уровней (Big/Micro как теги) — впереди.
3. **Решения и проблемы** — Solution, Problem (работа + решение + недобитый критерий), Aha Moment существуют только как текстовые ответы интервью, не как сущности.
4. **Сегменты** — нет Segment (кóровые работы + критерии + порядок приоритетов), нет каузальных критериев, нет Карты сегментов с экономикой (4 вопроса go/no-go).
5. **Интервью → граф** — заполненное интервью не превращается в структурные Job-записи с confidence (паттерн nmt-analyze-interviews).
6. **Критическая цепочка работ** — нет проекции графа на ось времени: разрывы, циклы, hand-off'ы, drop-off'ы, место Aha.
7. **RAT** — нет рискованных гипотез с приоритетом `(P × цена ошибки) / цена проверки`, RAT-карточек, RICE.
8. **Consideration Set** — 4 слота (знание графов, сравнение, продукт+вход, страхи) есть только в промпте агента.

## 3. Принципы реализации

- **Job = корневая сущность.** Узел графа получает опциональную «карточку» — граф остаётся лёгким для быстрого наброска, детализация по требованию (fidelity level 1/2/3 из канона: level 3 = то, что есть сейчас).
- Каждая фаза: модель в GraphCore → bump версии envelope с миграцией → UI → обновление промпта агента → тесты. Паттерн уже отработан (v1→v5).
- **Пререквизит из TODOS.md:** lossless round-trip неизвестных стадий envelope — сделать до v6, иначе новые секции будут стираться вторым писателем.

## 4. Фазы

### Фаза 1 — Карточка работы: 8 элементов + вес + тип (фундамент)
- `JobDetails` (опционально на `JobNode`): контекст, негативные эмоции, Consideration Set (4 слота), триггер, ожидаемый результат (расширяет verb), критерии успеха `[{ось, порог, ранг приоритета}]`, позитивные эмоции. Вышестоящая работа уже задана ребром графа — не дублировать.
- Вес: частота, бюджет, важность 1–10. Тип: enum из 6. Осознанность: conscious/unconscious.
- UI: инспектор-панель справа при выборе узла (как Level-1 запись канона); бейдж на узле «карточка заполнена».
- Envelope v6. Критерии успеха — отдельная под-сущность (на них ссылаются Problem, Aha, ценность).

### Фаза 2 — Семантика уровней и граница продукта
- ✅ Границa продукта внутри уровня (envelope v8): области уровня (`LevelZone`), интенты `addZone/renameZone/deleteZone/setJobZone`, `move` с областью; на канвасе и в PNG — пунктирная рамка со своим именем, узлы того же размера с пунктирным контуром; агент размечает `"zone"` в payload. Малые работы читаются как соседи кóровых по уровню, а не как декомпозиция.
- Осталось: тег уровня Big/Micro (+Super Big) относительно продукта вместо индекса; цвет/подпись полосы по типу, а не по номеру.

### Фаза 3 — Решения, Проблемы, Aha
- `Solution` (имя, DIY-флаг, ссылка на под-граф работ), связь Job↔Solution many-to-many.
- `Problem` = {job, solution, criterion_missed, сила 1–10}; `AhaMoment` = {событие, побитые критерии, позиция в цепочке}.
- UI: секция в инспекторе + список решений проекта. Цепочка «Работа → Решение → Проблема» как навигация.

### Фаза 4 — Сегменты и Карта сегментов
- `Segment`: кóровые работы (ссылки на узлы), порядок приоритетов критериев (8 канонических: price-first, done-for-me-first…), каузальные критерии, 4 вопроса экономики (ценность/маржа/спрос/масштаб + hard-blocker), вердикт focus/hold/not_ours.
- Карта сегментов: сравнительная таблица-вью (как selection screen из nmt-market-research).
- Один граф работ ↔ один сегмент (по канону граф принадлежит сегменту).

### Фаза 5 — Интервью → структурные работы (агент)
- Экстракция из заполненного интервью: Job-записи с 8 элементами + confidence (High/Medium/Low, hard gates «платил в прошлом / делал сам / конкретный эпизод» из nmt-analyze-interviews).
- Кластеризация интервью в сегменты по схожести кóровых работ + критериев; confidence сегмента (Solid/Emerging/Hypothesis).
- Расширить `AgentArtifactsPayload` и промпт; связь interview → извлечённые jobs → segment.

### Фаза 6 — Критическая цепочка работ
- Вью «цепочка»: проекция выбранного под-графа на ось времени при выбранном Solution. Узлы-шаги, разрывы (6 классов), циклы, hand-off'ы, drop-off = переключение Solution, позиция Aha (цель — максимально влево).
- Модель: `CriticalChain` поверх существующих рёбер «последовательность в уровне» — рёбра уже есть, добавить аннотации шагов.

### Фаза 7 — RAT и гипотезы ценности
- `RiskyAssumption`: позитивная формулировка, слой цепочки (market / segment+job / value / unit-econ / channels / custom), P × цена ошибки / цена проверки → авто-сортировка. RAT-карточка (5 строк из nmt-craft-value-proposition).
- `ValueHypothesis` каноничной формы «Для {сегмент} с {кóровая работа + критерий} закрываем эффективнее через {механика} …» + RICE (+бонусы за move-up-a-level / kill-a-Job).
- Справочник механик ценности (25 из канона) как подсказки при создании гипотезы.

### Фаза 8 — позже (по результатам)

## 5. Порядок и обоснование

1 → 2 — фундамент: всё остальное ссылается на критерии успеха и типизированные уровни. 3 → 4 — аналитическое ядро методологии (Job+Solution пара, сегмент как корень). 5 — превращает уже существующие интервью из текста в данные. 6–7 — операционный и стратегический слой. Каждая фаза самостоятельно полезна и шипается отдельно (v6, v7, … envelope).

## 6. Риски

- **Перегруз UI**: канон огромен; держать графовый набросок лёгким, детализация только по требованию (инспектор, не обязательные поля).
- **Второй писатель**: до v6 сделать lossless round-trip (TODOS.md), иначе агент/CLI сотрёт новые секции.
- **Валидация плана**: самая рискованная гипотеза — что структурные карточки нужны в ежедневной работе, а не только текст интервью. Дешёвая проверка: фаза 1 минимальной (только критерии успеха + важность), пожить неделю на реальном проекте, потом решать про 3–7.
